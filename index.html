How I approach a problem

From raw events
to reliable results.

The projects demonstrate two ways I approach engineering problems: making real-time visual feedback understandable and ensuring backend data is processed consistently.

01 / UNDERSTAND

Find the real friction

For the leaderboard: identify the risk of repeated API responses causing the same quiz event to be counted more than once.

02 / EXPLORE

Make information legible

Poll the API ten times with a five-second delay, collect response events, and identify each event by round ID plus participant.

03 / VALIDATE

Test before trusting

Use a Set to ignore duplicate events, aggregate each participant’s scores, sort totals in descending order, and submit the final leaderboard. Occasional API errors such as 502 responses may still need operational handling.
